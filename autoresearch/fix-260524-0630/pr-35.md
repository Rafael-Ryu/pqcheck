Closes #35.

## What changed
`ImportResolver` recorded `from <module> import *`, but `PythonDetector` never used that information. As a result, code such as:

```python
from hashlib import *
md5(b"x")
```

produced no finding.

This PR adds a demoted-confidence fallback for unresolved `ast.Name` calls. If a star-imported module contains a matching catalog entry, the detector emits that finding with `confidence=0.7`. `CIPHER-WRAPPER` is intentionally skipped because wrapper extraction depends on resolving qualified `algorithms.X` and `modes.Y` arguments.

This branch includes the #33 parser fix as a prerequisite so full verification passes while PR #38 is still pending.

## Tests
New unit coverage verifies:

- `from hashlib import *; md5(...)` emits `MD5` at confidence `0.7`
- `from cryptography.hazmat.primitives.hashes import *; MD5()` emits `MD5`
- non-crypto star imports remain silent
- unrelated names remain silent
- cipher wrapper markers are not emitted through this fallback
- explicit qualified calls are not double-emitted
