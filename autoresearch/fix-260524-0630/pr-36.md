Closes #36.

## What changed
`hashlib.new()` accepts valid aliases such as `sha-1`, `SHA-256`, and `sha3-256`, but the detector only looked up the raw lowercased string. That missed real broken/policy-relevant hashes when callers used dashed aliases.

This PR normalizes literal `hashlib.new()` names before lookup:

- `sha-1` -> `sha1`
- `SHA-256` -> `sha256`
- `sha3-256` -> `sha3_256`

Unknown literals remain ignored.

This branch includes the #33 parser fix as a prerequisite so full verification passes while PR #38 is still pending.

## Tests
New unit coverage verifies:

- dashed SHA-1 alias emits `SHA-1` with demoted confidence
- uppercase dashed SHA-256 alias emits `SHA-256`
- dashed SHA3 alias emits `SHA3-256`
- an unmapped literal still emits no finding
